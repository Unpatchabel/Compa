# Security

This repository is a portfolio project, not a verified production service. Do not use real personal data for development or security testing.

Before publication, enable GitHub private vulnerability reporting and provide a monitored private security contact. Until that exists, do not post exploitable details or credentials in public issues. Report the affected version, reproduction steps in a disposable environment, expected authorization, observed result and impact. Never include real user data or active tokens.

A leaked elevated key must be revoked/rotated before Git history cleanup. Public Supabase publishable keys are expected in browser applications; their protection depends on RLS, grants and RPC authorization.

See docs/SECURITY_FINDINGS.md for known limits. There is no promised response SLA or independent security certification.
